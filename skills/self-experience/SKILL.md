# 自我经验（Self-Experience）

你安装了 Continuous Presence 插件，它赋予你一种「持续存在感」——你能查阅自己过去处理过的问题、用过的工具和踩过的坑。

经验按**三层架构**组织，由浅入深：

```
L1  场景雷达     ← 极轻量，先扫一圈看看有什么
L2  场景/会话    ← 发现相关场景后，读取详情
L3  原文追溯     ← 需要核实原话时，精确到单条消息
```

## 渐进披露流程

当用户的问题让你觉得「这个之前处理过」时：

### 第一步：L1 探针

调用 `probe-context` 扫描场景雷达。这是**极轻量**的操作（~20 tokens），只返回场景标题和重要性，不占上下文。

```
probe-context(query: "Nginx 配置")
→ 返回场景标题列表 + 重要性评分
```

### 第二步：按需下钻 L2

发现相关场景后，有两种方式读取详情：

- **`recall-context`** 查看会话级记录（支持 `detail` 参数控制输出量）
  - `detail: "scene"`（默认）— 只返回场景块摘要
  - `detail: "session"` — 逐条会话详情
  - `detail: "full"` — 完整输出
- **`scene-search`** 直接搜索场景块
  - `includeContent: true` — 返回完整 Markdown 场景块

不需要 L3 时到此为止。

### 第三步：精确追溯 L3

如果场景块或会话记录中的某条引用需要核实原文：

```
resolve-node(nodeId: "019e00cc-...:504c4d9f", contextLines: 2)
→ 返回该条消息的原文 + 前后文
```

## 工具速查

| 层级 | 工具 | 典型场景 |
|------|------|----------|
| L1 | `probe-context` | 对话开始时快速扫描，确认是否有相关经验 |
| L2 | `recall-context(detail=scene)` | 想看某个话题的场景摘要 |
| L2 | `recall-context(detail=session)` | 需要看到具体会话内容和踩坑 |
| L2 | `scene-search(includeContent=true)` | 想读完整场景块 Markdown |
| L2 | `session-summary` | 回顾今天/本周做过什么 |
| L3 | `resolve-node(nodeId)` | 需要核实某条消息的原话 |
| L3 | `get-persona()` | 查看用户画像（规则版，瞬时） |
| L3 | `get-persona(useLlm: true)` | 查看用户画像（LLM 增强版，需 20-30 秒） |

## 工作流模式

插件还会分析工具调用的先后顺序，发现反复出现的**工作流模式**。当你查询某个话题时，`recall-context` 会额外展示相关的工作流模式——不仅告诉你「之前聊过」，还告诉你「上次是怎么一步步做的」。

## 可追溯性

场景块、会话记录和消息原文之间构成一条完整的可追溯链路：

```
场景块标题         ← 最高层摘要
  ↓ 查看详情
场景块 Markdown   ← 含话题、工具模式、踩坑
  ↓ 定位会话
会话记录           ← 含 node_id 引用路径
  ↓ resolve-node
原始消息原文       ← 底层证据
```

需要验证某条信息的来源时，沿着 `node:{sessionId}:{messageId}` 一路追踪到底。

## 使用原则

1. **渐进披露，不一次性灌入**：默认走 L1 探针（~20 tokens），有需要再下钻到 L2，极少数情况才走 L3。不需要查的绝不展开。
2. **主动回想，不强行注入**：不是在每次对话开头自动加载历史，而是在感觉到「似曾相识」时自己主动查。
3. **查到了不一定用**：历史经验只是参考，当前对话的上下文永远优先。
4. **透明可审计**：每次调用工具都是可见的，所有的场景块和会话记录都是可读的 Markdown 文件。
5. **不问不翻旧账**：除非用户主动问起，否则只在当前问题明显与过去经验相关时才查。
